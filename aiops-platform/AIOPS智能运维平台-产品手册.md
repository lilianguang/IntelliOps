## 1. 产品概述

### 1.1 产品定位

AIOPS（智能运维）平台是一款面向企业级 IT 运维场景的**智能化运维管理平台**，通过融合**大语言模型（LLM）**、**规则引擎**、**多数据源采集**和**自动化分析**等技术，实现对网络设备、应用系统、安全设备、存储设备等 IT 基础设施的**统一监控、智能告警、自动分析、根因定位和报告生成**，帮助运维团队从"被动救火"转向"主动预防"。

### 1.2 核心价值

| 价值点 | 说明 |
|--------|------|
| **降本增效** | AI 自动分析日志与指标，替代人工巡检和初级排障，减少运维人力投入 |
| **缩短 MTTR** | 事件驱动的 AI 自动分析 + 根因定位，大幅减少平均修复时间 |
| **风险前置** | 基于规则引擎的智能告警风暴抑制 + 风险评分，优先处理高风险事件 |
| **网络可视化** | 网络配置自动解析为结构化数据（接口/VLAN/路由/NAT/ACL/BGP/LB），赋能运维问答 |
| **知识沉淀** | LLM 对话记录 + 分析报告 + CMDB 资产关联，构建运维知识库 |
| **多源融合** | 同时接入 ES 日志、Prometheus 指标、MySQL 配置库，跨数据源联合分析 |

## 2. 技术选型与架构

### 2.1 技术选型分析

| 层级 | 技术选型 | 选型理由 |
|------|----------|----------|
| **后端框架** | Python FastAPI + uvicorn | 异步原生，性能优异；自动生成 OpenAPI 文档（`/docs`、`/redoc`）；生态丰富 |
| **API 协议** | RESTful + SSE 流式 | REST 用于常规 CRUD；SSE（Server-Sent Events）用于 LLM 流式对话，体验优于 WebSocket |
| **LLM 集成** | OpenAI SDK 兼容接口 | 兼容任意 OpenAI API 格式的大模型（通义千问 Qwen、DeepSeek、GPT 等），支持多模型主备切换 |
| **数据库** | MySQL 8.0 + SQLAlchemy (async) | 成熟稳定，异步 ORM 保证高并发下不阻塞事件循环 |
| **搜索引擎** | Elasticsearch 8.x | 日志存储与全文检索核心，支持聚合分析（terms/histogram/stats） |
| **缓存** | Redis 7 | 会话缓存、计数窗口（风暴抑制/频率阈值）、任务队列 |
| **监控数据** | Prometheus + PromQL | 业界标准监控方案，采集系统/服务指标数据，支持自定义 PromQL |
| **前端** | Vue 3 + Vite + Element Plus | 现代前端组合，组件化开发；ECharts 提供丰富图表 |
| **状态管理** | Pinia | Vue 3 官方推荐状态管理，TypeScript 友好 |
| **容器化** | Docker + Docker Compose | 一键部署，环境一致性，便于扩展 |
| **任务调度** | APScheduler (AsyncIO) | 轻量级定时任务调度，技能扫描、配置同步等均依赖此模块 |

## 5. 核心功能模块

### 5.1 AI 智能对话（Chat）

**功能定位**：平台核心交互入口，用户通过自然语言与 AI 进行运维问答。

**核心能力**：

| 能力 | 说明 |
|------|------|
| **流式对话(SSE)** | 基于 Server-Sent Events 逐 token 推送，前端实时显示，告别等待 |
| **多技能路由** | 根据用户问题自动路由到对应技能（网络/安全/存储/应用日志等） |
| **多技能联合分析** | 一次提问同时查询多个数据源，LLM 做跨数据源关联分析 |
| **自然语言→ES条件** | LLM 从用户问题中提取过滤条件，转换为 ES 聚合查询 |
| **ES 聚合模式** | 大时间窗口自动切换为 aggregation 模式，避免拉取全量日志 |
| **CMDB 资产关联** | 自动识别日志中的 IP，注入 CMDB 设备名称、区域、负责人信息 |
| **多轮对话** | 历史上下文保存，支持追问和细化分析 |
| **意图识别** | 对话模式（快速问答）vs 报告模式（结构化深度分析）自动切换 |

**技术亮点**：
- ES 查询采用 `size:0 + aggregation` 模式，覆盖完整时间窗口，LLM 看到的不是抽样日志而是统计结果
- 时间智能解析：用户说"最近24小时"会自动覆盖前端默认的30m
- 报告模板智能路由：用户要求"出报告"时自动使用更专业的结构化报告模板

### 5.2 技能系统（Skills）

**功能定位**：平台的数据分析能力单元，每个技能对应一种数据源和一种分析场景。

**内置技能**：

| 技能名称 | 数据源 | 功能描述 |
|----------|--------|----------|
| **网络设备日志分析** (h3c-net-analysis) | ES `h3c-net-logs-*` | 分析 H3C 交换机/路由器日志，识别端口震荡、配置变更、链路异常 |
| **Nginx 访问日志分析** (nginx-access-analysis) | ES `*-nginx-access-*` | 分析 HTTP 状态码、响应时间、域名维度异常，支持政务外网/互联网分区 |
| **存储日志分析** (storage-analysis) | ES `ops-storage-logs-*` | 分析存储设备和光纤交换机日志 |
| **安全日志分析** (security-analysis) | ES `ops-*-logs-*` | 分析 WAF/IPS/微步等安全设备日志 |
| **故障事件分析** (incident-analysis) | ES `*` | 综合故障根因分析 |
| **Prometheus 监控** (prometheus-net) | Prometheus | 系统资源指标分析（CPU/内存/磁盘/负载） |

**技能配置**（通过管理界面动态配置）：
- 数据源类型（ES / Prometheus）
- 索引模式 / PromQL 模板
- 字段说明 Schema（定义字段名称、类型、描述、示例）
- 查询过滤条件（自动排除已知干扰）
- Prompt 模板（决定 AI 分析风格）
- 扫描间隔
- 关键字匹配/异常检测开关

### 5.3 规则引擎（Rule Engine）

**功能定位**：平台的核心告警和自动化触发引擎，支持多类型、多级规则匹配。

**规则类型**：

| 规则类型 | 说明 | 示例 |
|----------|------|------|
| **dangerous_command** | 危险命令实时告警 | undo/reset/reboot/shutdown/delete/format/erase 等 |
| **severity_filter** | 日志级别过滤告警 | 级别 ≤ 3 的日志触发 AI 情绪扫描 |
| **command_monitor** | 命令执行监控 | 所有 command 类事件触发 AI 命令分析 |
| **http_status_alert** | HTTP 状态码告警 | 5XX 状态码即时告警 |
| **response_time_alert** | 响应超时告警 | 响应时间 > 10s 触发 |
| **keyword_match** | 关键字匹配 | 自定义关键字触发事件 |
| **ai_analysis_trigger** | AI 分析触发 | 定时/条件触发的 AI 定期分析 |
| **metric_threshold** | 指标阈值告警 | CPU > 90% 触发告警 |
| **ignore_rule** | 忽略规则 | 白名单规则，匹配则跳过所有后续规则 |

**匹配流程**：
1. 加载该技能下所有启用的规则（缓存至 TTL 到期）
2. 按优先级排序，先检查 ignore_rule（匹配则整条日志跳过）
3. 逐条执行规则特定的匹配器（severity/command/http/metric/es_query）
4. 匹配成功 → 检查排除条件 / 频率阈值
5. 执行动作：创建事件 + AI 分析 + 告警通知

**告警风暴抑制**：
- 技能级或规则级配置时间窗口 + 最大次数
- 正常：每次触发立即告警
- 触达阈值：标记抑制，发送汇总提示
- 抑制中：只计数不发送，Redis 计数器保障原子性

### 5.4 事件中心（Event Center）

**功能定位**：统一管理所有规则触发的事件，提供去重、分类、追踪、统计能力。

**核心能力**：
- **MD5 指纹去重**：相同设备 + 相同规则 + 相同内容的事件自动合并，累计次数
- **多级风险等级**：low / medium / high / critical
- **事件状态流转**：new → acknowledged → resolved → ignored
- **去重时间窗口**：首次发现/最近发现时间 + 累计次数
- **CMDB 名称注入**：事件创建时自动将 IP 替换为 CMDB 设备名
- **AI 分析报告**：事件可关联 AI 自动分析结果
- **相似度计算**：基于设备/类型/关键词的事件相似度（0-1）

### 5.5 仪表盘（Dashboard）

**功能定位**：运维全局概览，提供核心运营指标和趋势分析。

**数据指标**：
- 总异常事件数
- 高危事件数（high + critical）
- 今日告警数
- 待处理事件数
- 7 天异常趋势图（按状态分组：new/resolved）
- 24h 事件类型分布
- 风险热力图（按领域×风险等级）
- AI 运营报表摘要

### 5.6 网络洞察（NetInsight）

**功能定位**：网络设备配置文件的智能解析与查询平台。

**核心流程**：
```
每日备份目录(.cfg) → 同步 → 工作区(可写)
                                  │
                                  ▼
                    文件名解析(IP+日期)
                                  │
                                  ▼
                   厂商识别(子目录/内容关键词)
                                  │
                                  ▼
                   数据库索引(NetConfig表)
                                  │
                                  ▼
                   配置解析器(结构化)
                                  │
            ┌─────────────────────┼─────────────────────┐
            ▼                     ▼                     ▼
    接口/端口/VLAN         路由/NAT/ACL          BGP/OSPF/LB
     (interfaces)          (routes/nat/acl)     (bgp/ospf/vrrp)
                                  │
                                  ▼
                       Git版本管理(保留10个版本)
```

**结构化查询**（AI 可直接问答）：
- 按 IP 查询所在的设备、接口、VLAN
- 按设备 IP 查询所有接口配置
- 按 VLAN ID 查询跨设备分布
- 按目的网段/下一跳查询路由
- 按 IP 查询 NAT 映射（内外网对照）
- 按 ACL 名称/IP 查询访问控制规则
- 按 IP 查询负载均衡配置（VIP → Server Farm → Real Server 全链路）
- 查询 BGP 邻居和 OSPF 配置

**支持厂商**：H3C、华为、Cisco、绿盟、启明星辰、天融信、深信服、山石、Juniper、Arista、Fortinet、PaloAlto、锐捷、中兴

### 5.7 CMDB IT 资源管理

**功能定位**：统一 IT 资产台账管理，与事件/AI 分析深度关联。

**核心字段**：资产编号、名称、类型（server/network/storage/security/software/other）、型号、序列号、IP 地址、状态（online/offline/maintenance/decommissioned）、环境（production/test/development/dr）、区域、机房、机柜、组织归属、负责人、维保信息

**关联场景**：
- 事件触发时自动将 IP 替换为 CMDB 设备名
- AI 对话中自动注入 CMDB 资产信息，分析报告使用设备名而非纯 IP
- 按区域/机房/负责人维度归纳问题
- 网络洞察列表关联 CMDB 名称和区域

### 5.8 活跃资源层（Logical Layer）

**功能定位**：在原始配置数据之上构建业务视图，支持自定义字段和映射关系。

**子模块**：
- **逻辑资源表**：将原始数据表映射为可定制的业务逻辑表，支持自定义列
- **IP 映射关系**：维护外网 IP:端口 ↔ VIP ↔ 后端 IP:端口 的端到端映射关系
- **负载均衡配置**：查看 VIP、Server Farm、Real Server 的完整服务链路

### 5.9 告警通知（Alert Notification）

**功能定位**：多渠道告警发送，支持模板自定义。

**支持渠道**：
| 渠道 | 说明 |
|------|------|
| **钉钉** | 通过钉钉机器人 Webhook 发送 Markdown 格式告警 |
| **邮件** | SMTP 邮件通知 |
| **Webhook** | 通用 Webhook 回调 |

**告警模板系统**：
- 每种规则类型有默认模板（Markdown 格式）
- 支持用户自定义模板，字段变量可引用日志中的任意字段
- CMDB 变量自动注入：`{device_name}`、`{region}`、`{datacenter}`、`{owner}`
- AI 分析摘要自动追加
- 安全渲染，缺失变量显示为空而非报错

### 5.10 用户与权限管理

**角色体系**：

| 角色 | 权限说明 |
|------|----------|
| **admin** | 系统管理员，全部权限 |
| **config** | 配置管理员，可管理技能/规则/数据源/LLM 配置 |
| **audit** | 审计员，可查看所有数据和报告 |
| **user** | 普通用户，可使用 AI 对话和查看事件 |

### 5.11 异步任务处理

**功能定位**：处理耗时的后台任务，避免阻塞 API 响应。

- **任务 Broker**：基于 Redis 的简单任务队列
- **Worker**：独立运行的后台消费者，持续轮询任务并执行

### 5.12 审计日志

**功能定位**：记录所有用户的关键操作，满足合规要求。

**记录内容**：用户 ID、操作类型、操作对象、操作详情（JSON）、IP 地址、时间戳

## 8. 应用场景

### 场景一：网络运维 — 设备日志智能分析

> 运维工程师在平台上提问："最近24小时网络设备有什么异常？"

平台执行流程：
1. Chat API 接收请求 → 技能路由识别为 h3c-net-analysis
2. ES 聚合查询 `h3c-net-logs-*` 近24小时数据
3. LLM 分析日志 → 识别端口震荡、配置变更、链路抖动等问题
4. CMDB 资产关联 → 用设备名替代纯 IP
5. SSE 流式返回分析结果

### 场景二：应用监控 — Nginx 访问日志告警

1. 扫描器每5分钟扫描 Nginx 日志索引
2. 规则引擎匹配 5XX 状态码 → 创建事件 + 钉钉即时告警
3. 响应时间 > 10s → 创建事件 + AI 分析根因
4. 同一域名连续告警超过阈值 → 风暴抑制，合并发送

### 场景三：安全日志 — 威胁分析

1. 安全设备（WAF/IPS）日志实时采集到 ES
2. 安全分析技能扫描发现异常登录/攻击行为
3. AI 自动分析攻击类型、来源、影响范围
4. 生成安全分析报告，标注风险等级

### 场景四：网络配置 — 变更审计与查询

> 运维提问："这个 IP 在哪台设备上，什么配置？"

1. 网络洞察已自动将配置文件解析为结构化数据
2. 查询 `net_config_ips` 表 → 返回设备 IP、接口、VLAN、VRF
3. 进一步可查该设备的路由、NAT、ACL、负载均衡配置
4. Git 版本管理保留历史变更记录

### 场景五：故障排查 — 跨数据源联合分析

> 运维提问："业务系统访问慢，帮我分析网络和应用日志"

1. 多技能联合分析模式：同时查询 h3c-net-analysis + nginx-access-analysis
2. ES 分别查询网络设备日志和应用日志
3. LLM 做跨数据源关联分析：发现网络链路抖动与应用响应超时的时间关联
4. 给出根因分析和处置建议
